## 대기 중

### 1. URP 2D — Light2D가 없으면 스프라이트가 전부 까맣다 (2026-08-19)

URP 2D에서 `SpriteRenderer`의 기본 머티리얼은 `Sprite-Lit-Default`다.
씬에 `Light2D`가 하나도 없으면 **코드는 정상인데 화면만 새까맣게** 나온다.
빈 씬에서 런타임으로 오브젝트를 만들 때 특히 잘 걸린다 → 전역 광원을 보장하는 코드를 넣을 것.

### 2. "카메라가 플레이어를 따라가는데 목표점이 카메라 기준"이면 무한 가속 (2026-08-19)

마우스 추종 조작에서 목표점을 `Camera.ScreenToWorldPoint(마우스)`로 잡고,
카메라가 플레이어를 따라가게 만들면 **커서가 화면 가장자리에 있을 때 목표점이 플레이어와 함께
도망가서 영원히 가속한다.** 커서가 게임 창 밖에 있을 때(에디터에서 Play 직후) 바로 재현된다.

→ 플레이어와 목표점을 **둘 다 월드 경계로 clamp**한다. 카메라만 clamp하면 안 된다.
   장르 무관하게 "커서를 향해 이동 + 추적 카메라" 조합이면 전부 해당된다.

### 3. 헤드리스 게임 시뮬레이션을 결정론적으로 만드는 법 (2026-08-20)

Unity 배치 모드에서 게임 루프를 돌려 밸런스를 자동 측정할 때 반드시 필요한 3종 세트.
**하나라도 빠지면 측정값이 흔들리는데, 표만 보면 정상처럼 보여서 알아채기 어렵다.**

1. **`Time.timeScale`이 아니라 `Time.captureDeltaTime`** — 배치 모드는 프레임이 매우 빨라
   timeScale을 올려도 프레임당 deltaTime이 미세하다. 12,000프레임을 돌려도 게임 시간은 5초.
   captureDeltaTime은 프레임당 게임 시간을 고정한다
2. **절대 시각을 코드에서 쓰지 않는다** — `Time.time`, `DateTime.Now`. 실행마다 시작값이 달라
   결과가 갈린다. 게임 오브젝트는 자기 수명 기준 타이머를 따로 갖는다
3. **워밍업 실행 하나를 버린다** — 부팅 직후 첫 회는 에셋 로딩·JIT 때문에 항상 다르다

+ 난수는 전부 시드 고정. + 배치 실행끼리 겹치지 않게 락을 건다
(두 Unity 인스턴스가 같은 프로젝트를 열면 `0xC000013A`로 죽는데 원인이 안 보인다).

### 4. PowerShell 5.1은 BOM 없는 `.ps1`을 ANSI로 읽는다 (2026-08-19)

한글 주석이 있는 스크립트를 UTF-8(BOM 없음)로 저장하면 **파싱 자체가 실패**한다
(`Array index expression is missing`, `The string is missing the terminator` 등 엉뚱한 에러).
→ `.ps1`은 **UTF-8 with BOM**으로 저장할 것.

### 5. Unity 6 URP 17은 2D 런타임이 별도 어셈블리 (2026-08-19)

`Light2D`는 `Unity.RenderPipelines.Universal.Runtime`이 아니라
**`Unity.RenderPipelines.Universal.2D.Runtime`**에 있다.
asmdef 없이 쓸 땐 자동 참조라 안 드러나고, 어셈블리를 분리하는 순간 터진다.

## 0. 한 줄

**도구를 늘려가며, 떠다니는 우주 쓰레기를 빨아들이는 게임.**

- 장르: 2D 픽셀아트 · 수집형 로그라이트 (지역 단위 세션)
- 플랫폼: PC(Windows) · 웹(WebGL) 데모
- 엔진: **Unity 6.3 LTS (URP 2D)**
- 조작: **좌클릭 홀드 = 이동 · Shift(우클릭) = 대시**
- 임시 제목: **SALVAGE RUN / 살비지런** 🟡 공개 전 확정

## 1. 핵심 루프

```
지역 선택 → 진입 → 도구가 자동으로 쓰레기를 빨아들인다 → 연료 소진 → 자동 귀환
   → 정산 → 테크트리 해금 → 더 좋은 도구로 다시
```

한 바퀴 목표: **60~90초.** (2026-08-19 개정 — 이전 목표는 3~5분이었다)

### 🔴 재미가 나오는 지점 (rev.2에서 바뀐 부분)

**"도구가 늘어나면서 화면이 점점 요란해지는 것."**

사용자 방향(2026-08-19): *"스피디한 느낌으로, 후반으로 갈수록 도파민이 터지는 게임."*
→ 런을 60~90초로 짧게, 대시로 속도감을 주고, 후반 지역일수록 유입과 수익이 폭발하게 한다.

rev.1에서는 "돌아갈까, 하나만 더 주울까"가 축이었다. **자동 귀환 + 용량/무게 제거로 런에서
잃는 것이 없어졌으므로 그 축은 사라졌다.** 지금 남은 상품은 두 개다.

1. **수집 손맛** — 빔이 붙고, 자석이 훑고, 드론이 물어오고, 그물이 터지는 순간
2. **도구가 늘어나는 감각** — 처음엔 빔 하나, 나중엔 여섯 개가 동시에 돈다

그러므로 **모든 기능은 "이 두 가지를 진하게 만드는가"로 판단한다.**

- 강화하는 것 → 넣는다 (도구, 이펙트, 수집 피드백, 도구 조합)
- 무관한 것 → 미룬다 (스토리, 캐릭터, 도전과제, 커스터마이징)

## 2. 리스크 — 시간뿐이다 (2026-08-19 사용자 결정)

| 항목 | 규칙 |
|---|---|
| 연료 소모 | **추진 출력에 비례.** 버튼을 안 누르면 소모 0 |
| 대시 | Shift/우클릭. 커서 방향 순간 가속, 연료 소모 + 쿨다운 |
| 연료 0 | **자동 귀환.** 조작 불가, 수집 불가, 지역별 귀환 시간만큼 시간을 잃는다 |
| 화물 | **전부 지킨다.** 잃는 것은 없다 |
| 용량 | **없다** |
| 무게로 인한 감속 | **없다** |

> ⚠️ **이 결정의 대가를 문서에 남겨 둔다.** 잃는 것이 없으므로 이 게임은 인크리멘탈 쪽으로
> 이동했고, [[content-design]]에서 확인한 경쟁작(Space Rock Breaker)과 **같은 칸**에 서게 됐다.
> 차별점은 이제 "잃는다"가 아니라 **도구 빌드와 수집 손맛**이어야 한다.
> 그쪽이 얇으면 우리는 그 게임의 열화판이 된다 — 그래서 §1의 판단 기준이 그것 하나다.

## 3. 두 층 구조

| 층 | 범위 | 런이 끝나면 |
|---|---|---|
| **런 층** | 이번 진입에서 모은 크레딧, 남은 연료 | 정산되어 사라진다 |
| **영구 층** | 크레딧, **테크트리 해금**, 지역 해금 | 남는다 |

로그라이크적 "소실"은 없다. 런은 **한 세션의 채굴 효율**을 겨루는 단위다.

## 4. 🔴 플레이타임은 테크트리가 결정한다

사용자 지시: *"이걸로 인해서 우리 게임의 플레이 타임이 걸려 있어."*

**35개 노드 · 4계열 · 총 약 94,000 크레딧.** 계산 근거와 노드 목록은 [[content-design]].

| 구간 | 대략 |
|---|---|
| itch 데모 체험 | 30~60분 (지역 1~2, 노드 8개 내외) |
| 본편 1회차 | **8~10시간** (전 노드 해금) |

계열: **견인**(도구를 늘린다) · **선체**(슬롯·가치) · **추진**(연료·조작) · **탐사**(지역 해금)

> 🔴 테크트리 총비용을 건드리는 것은 곧 **게임 분량을 건드리는 것**이다.
> 밸런스 조정이 아니라 스코프 변경으로 취급한다.

## 5. 지역 (스테이지) — 아레나는 화면 하나

**맵 = 화면 하나. 카메라는 움직이지 않는다.** (2026-08-19 결정)
🔴 **쓰레기는 아레나 바깥에서 흘러들어와 가로지르고, 반대편으로 나가면 사라진다.**
유한한 필드를 청소하는 게 아니다 — 놓치면 정말 놓친다. 배는 경계 밖으로 못 나간다.

5개 지역, 난이도 순: 기지 궤도 → 폐선 항로 → 잔해장 → 파괴된 정거장 → 심연.
**지역마다 크기는 같다.** 차이는 쓰레기 밀도(55→120) · 등급 · 연료 소모 배수 · 자동 귀환 시간.
해금은 **탐사 계열**이 한다.

> 🔴 카메라 고정을 택한 이유: 도구 6개가 동시에 도는 게 상품인데, 그게 화면 밖에서
> 벌어지면 상품이 안 보인다. GIF 유통에도 전장이 한 화면에 담기는 쪽이 유리하다.

## 6. 도구 8종

도구는 **전부 자동으로 작동한다.** 플레이어가 하는 일은 배를 좋은 자리에 두는 것뿐이다.

| 도구 | 성격 |
|---|---|
| 견인 빔 | 시작 장비. 가장 가까운 하나를 강하게 |
| 자석 그리퍼 | 반경 안 전부를 상시로 약하게 |
| 회수 드론 | 자율 비행, 레벨당 1기 |
| 그물 발사기 | 커서 방향 광역 일격, 쿨다운 |
| 절단 레이저 | **대형 잔해 해금** — 없으면 아예 수집 불가 |
| 자동 분류기 · 연료 정제기 · 스캐너 | 상시(패시브), 슬롯을 차지하지 않는다 |

### 🔴 도구에 붙은 유일한 단점 — 위험물

먹으면 크레딧이 없고 **연료가 깎이는** 쓰레기가 4종 있다(붉은 테두리로 상시 표시).

| | 위험물을 |
|---|---|
| **자석 · 그물** | 가리지 않고 빨아들인다 |
| **빔 · 드론** | 건너뛴다 |

그래서 **자석을 키울수록 위험물도 더 먹는다.** "도구를 키우면 무조건 이득"을 깨는 장치이고,
실측에서 실제로 작동했다 — 시작 조합 3~7개 vs 후반 조합 12~29개. ([[balance-log]])

**슬롯은 2개로 시작해 선체 계열로 5개까지.** 움직이는 도구만 슬롯을 먹는다.
🟡 장착 도구를 플레이어가 고르는 UI는 아직 없다(카탈로그 순서대로 자동).

## 7. 설계 원칙

1. **수집 손맛을 방해하는 건 전부 뺀다.** 컷신, 대사창, 화면을 가리는 UI.
2. **한 판은 60~90초.** 짧고 굵게 — 끝나자마자 다시 출항하고 싶어야 한다.
3. **커서 위에 얹어 두면 연료를 쓰지 않는다.** 생각하는 시간에 벌을 주지 않는다.
4. **도구는 자동으로 돈다.** 조작 부담을 늘려 손맛을 만들지 않는다.
5. **그레이박스 먼저, 도트는 나중.**
6. **원칙은 코드로 강제한다.** 밸런스는 `GameContent`/`RunConfig` 에셋 한 곳에만.

## 8. MVP 범위

### 넣는다

- 마우스 추종 조작 + 출력 비례 연료 소모
- 지역 5개 · 쓰레기 12종 · 도구 8종 · 테크노드 35개
- 자동 귀환 → 정산 → 격납고(지역 선택 + 테크트리)
- 수집 연출(빔·자석 링·그물 섬광·드론·팝업)
- WebGL 빌드

### 🚫 안 할 것 목록

> 이게 없으면 기능이 무한히 는다. 하고 싶어질 때마다 여기 적고 넘어간다.

- 멀티플레이 · 온라인 리더보드
- 스토리, 컷신, NPC 대사
- **적 AI / 전투** (수집 게임이다. 전투를 넣으면 만들 것이 3배가 된다)
- 보스전
- 우주선 외형 커스터마이징
- 3D, 모바일 포팅
- 스팀 도전과제·클라우드 (스팀 페이지 여는 시점까지 보류)
- 절차적 생성 고도화

## 9. 기술 결정 (되돌리기 비싼 것부터)

| 결정 | 값 | 이유 |
|---|---|---|
| 엔진 | Unity 6.3 LTS (6000.3.22f1) | 설치 완료 2026-08-19 |
| 렌더 | URP 2D (Universal 2D 템플릿) | 2D Light |
| 조작 | **홀드 이동 + 대시**, 커서와의 거리로 출력 결정 | 안 누르면 연료 0. 대시가 속도감을 담당 |
| 물리 | Rigidbody2D + 감쇠 | 관성이 손맛을 만든다 |
| 데이터 | `GameContent` SO 하나에 쓰레기·지역·도구·테크 전부 | 에셋이 늘면 관리가 샌다 |
| 저장 | JSON → `persistentDataPath`, `version` 필드 포함 | WebGL(IndexedDB) 호환 |
| 테크 저장 | **노드 id 문자열 목록** | 배열 인덱스로 저장하면 노드 순서를 못 바꾼다 |
| 입력 | Input System (구 API도 전처리기로 병행) | 설정 차이로 시간 버리지 않기 |
| PPU | 🟡 미정 (16 vs 32) | 아트 시작 직전에 확정. 정하면 전 에셋 재작업 |

1. **제목 확정** — 스팀/itch 주소가 여기서 나온다. 공개 전에.

## 11. 이 브리프가 틀렸을 때

플레이해서 **"도구가 늘어도 별로 안 신난다"**가 나오면, 그때는 UI나 이펙트가 아니라
**도구 설계 자체**를 다시 본다. 후보:

- 도구 조합 시너지 (자석 + 그물이 겹치면 폭발적으로)
- 지역별 특수 규칙 (여기서는 드론이 두 배 등)
- 잃는 것을 다시 넣기 (rev.1의 귀환 도박으로 복귀)

축을 바꾸면 이 문서를 고치고 이유를 [[decisions]]에 적는다.

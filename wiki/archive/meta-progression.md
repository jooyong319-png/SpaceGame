# meta-progression — 영구 성장 (rev.14)

> **2026-09-02 갱신.** 원래 *"죽어도 아무것도 안 남는다"*를 메우려고 만든 층인데,
> 레벨업·카드가 없어진 지금은 **성장이 여기밖에 없다.**
> 수치 정본은 `Scripts/Data/TechTreeDefaults.cs` → `GameContent.asset`.

---

## ⚠️ 테크트리는 2026-08-20에 한 번 걷어냈던 것이다

`decisions`에 "테크트리 노드 격자 — 재미 대비 구현비가 최악"이라고 적어 두고 폐기했다.
지금 다시 만든 이유는 **그때와 다른 물건**이기 때문이다.

| | 그때 (폐기) | 지금 (구현) |
|---|---|---|
| 대상 | **런 안의** 성장 | **런 밖의** 영구 성장 |
| 문제 | 런 카드와 역할이 겹쳤다 | 겹치는 게 없다 — 메타가 **0**이었다 |
| 근거 | — | 뱀서도 골드 상점으로 같은 걸 한다 |

🔴 **이 구분을 잃으면 같은 실수를 반복한다.** 테크트리가 런 안으로 들어오려 하면 막을 것.

## ⬜ 세 층이었는데 한 층이 됐다

```
런 안 (카드)        이번 판의 빌드      — ⬜ 2026-08-26에 폐지
영구 (테크트리)     무기 · 강화 전부     — 🔴 이제 여기가 전부다
영구 (우주선)       시작 스탯           — 남아 있지만 무기는 안 정한다
```

🔴 **성장이 한 층으로 모였다는 것이 지금 이 게임의 성격을 정한다.**
판 안에서는 아무것도 안 자라고(레벨업 없음), **판이 끝나야 자란다.**
그래서 *"한 판을 잘 푸는 재미"*가 없고 **한 판은 채굴 시간**이다 —
2026-08-27에 사장님이 *"파밍이 재미가 없다"*고 하신 것과 **같은 뿌리**다([[playtests]]).

## 재화 6종 — 구역마다 하나씩 열린다

| 재화 | 처음 나오는 구역 | 덩어리 크기 |
|---|---|---|
| **고철** | 1구역 | 6 |
| **회로** | 2구역 | 3 |
| **코어** | 3구역 | 2 |
| **초합금** | 4구역 | 1 |
| **냉각결정** | 5구역 | 1 |
| **동위원소** | 6구역 | 1 |

🔴 **깊은 재화일수록 덩어리가 작다.** 값이 비싸서가 아니라
**노드 비용의 자릿수가 다르기 때문**이다 — 고철은 1600씩 드는데 코어는 12다.
그래서 코어 두 개가 고철 수백 개만큼 무겁고, **6칸에 뭘 실을지가 여기서 갈린다.**

⚠️ 8/26에 6종으로 늘리면서 **버는 쪽만 만들고 쓰는 쪽을 안 만들었다.**
초합금 이상이 떨어지기만 하고 쓸 데가 없어서 **3구역에서 트리가 전부 열렸다** —
4·5·6구역에 갈 이유가 게임 안에 없었다. 8/27에 끝단 노드 13개에 붙여 고쳤다.

드랍률은 `StageField.RollMaterials` — **티어가 높을수록 좋은 게 나온다.**

## 테크트리 113 노드

```
        (-x,+y) 기동  ┃  화력 (+x,+y)
        ──────────── 뿌리 ────────────
        (-x,-y) 선체  ┃  수집 (+x,-y)

               아래 바깥 = 무기 특색
               위쪽 바깥 = 특수 (시작 조건)
```

| 계열 | 성격 |
|---|---|
| 선체 · 기동 · 화력 · 수집 | 기본 축 (연료 · 속도 · 피해 · 흡수) |
| **무기 4종** | 여는 노드 + 무기별 가지 |
| **발동형** `pr1~pr14` | 확률로 터지고 · 옮겨붙고 · 두 번 쏜다 |
| **드롭형** `dr1~dr12` | 무엇이 얼마나 떨어지는가 |
| **견인형** `tw1~tw7` + `haul1` | 칸 · 무게 · 드론 · **직송 드론** |
| **보스형** `bs1~bs7` | 보스 피해 · 탄 저항 · 보스 재화 |
| **연료형** `fu1~fu7` | 최대치 · 감소 속도 · 회복량 |

🔴 2026-08-26에 47 → 113으로 늘리며 세운 기준: **숫자만 오르는 노드는 더 안 만든다.**
이미 충분하고, 살 때 아무 생각이 안 든다. 새로 넣은 것은 전부 *판이 굴러가는 모양*을 바꾼다.

⚠️ **정의만 하고 아무도 안 읽는 효과를 만들지 말 것.** 이 프로젝트에서 여러 번 사고였다 —
`TechEffect`에 값을 넣고 `RunStats`가 받는데 **게임이 그 필드를 안 읽으면**
사장님이 재화를 쓰고 아무 일도 안 일어난다. 컴파일도 스모크도 통과한다.
→ 스모크 `EveryTechNodeChangesSomething`이 노드마다 혼자 찍은 값을 기본값과 대조한다.
   ⚠️ 다만 그건 `BuildStats`까지만 본다. **읽는 곳이 있는지는 grep으로 따로 세야 한다.**

### 선은 데이터가 아니다

`requires`에서 자동으로 그린다. 선을 따로 저장하면
**"화면엔 이어져 있는데 안 열린다"**가 반드시 생긴다.

### 랭크마다 비용이 오른다 (`costGrowth`)

균일하면 후반에 잔돈이 남아 **아무 의미 없이 다 찍게 된다.**
다 찍힌 트리는 선택이 없는 트리다.

## 특수 노드가 제일 비싼 이유

**판이 시작되는 모양**을 바꾸는 것이라 숫자 노드 수십 개보다 체감이 크다.

- `화물 정렬기` — 짐이 덜 무겁다
- `화물 증설` — 끌 수 있는 칸 +2
- `숙련 정비` — 시작 무기 레벨 +1
- `과부하 정비` · `암거래망` · `불침 설계` — 계열 끝 노드 (깊은 재화가 든다)

⬜ 레벨업·카드가 없어지면서 `사전 조율`(레벨 +1)·`예비 설계도`(카드 선택지 +1)는
**읽는 곳이 없어졌다.** 효과(`StartLevel`·`CardChoices`)는 enum에 남아 있지만
노드가 안 쓴다 — 되살릴 일이 없으면 지워도 된다.

## 우주선 6척 — 🔴 스탯 묶음이 아니다

무기를 한 판에 둘만 갖는 구조라, **우주선이 정하는 시작 무기가 조합의 절반을 미리 결정한다.**
우주선을 고르는 것 = "어떤 계열로 갈까"를 고르는 것이다.

| 배 | 시작 무기 (계열) | 성격 |
|---|---|---|
| 정비선 · 핸디 | 회전 절단날 (절삭) | 표준. **무료** |
| 포경선 · 하푼 | 견인 작살 (관통) | 사거리 +25%, 연료 -20% |
| 굴착선 · 그라인더 | 흡입 소용돌이 (장판) | 연료 +45%, 추진 -15% |
| 폭파선 · 블래스트 | 압축 폭탄 (폭발) | 화력 +35%, **충돌 피해 증가** |
| 전기선 · 아크 | 정전기 방출 (전기) | 쿨다운 -28%, 화력 -15% |
| 견인선 · 타이탄 | 중력 우물 (중력) | 흡수 +50% 크레딧 +30%, 화력 -20% |

### 왜 계열마다 하나씩인가

같은 계열 배가 둘 있으면 **그 둘은 사실상 같은 배**다. 조합이 같아지기 때문이다.
새 배를 추가할 때도 이 규칙을 지킬 것 — 아니면 계열을 먼저 늘려야 한다.

### 왜 전부 플러스가 아닌가

🔴 **전부 플러스면 나중에 해금한 배가 항상 좋아지고, 그러면 선택이 사라진다.**
강한 곳이 있으면 약한 곳이 있어야 "이 판엔 이 배"가 성립한다.
폭파선의 `contactResist`는 **음수**다 — 맞으면 더 아프다.

### 테크는 더하기, 우주선은 곱하기

적용 순서가 정해져 있다: **테크트리 → 우주선**.
반대로 하면 우주선 배수가 테크 보너스를 못 받아
"테크를 올릴수록 배 차이가 줄어드는" 이상한 곡선이 된다.
